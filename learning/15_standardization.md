> 学習週：Week 12

## 1. 標準化の目的

```
標準化 = 「誰がやっても同じ結果になる」状態を作ること

標準化されると：
  ① 品質が安定する（人による差がなくなる）
  ② 教育・引継ぎが容易になる
  ③ 改善の効果が測定できる（ベースラインが明確）
  ④ 異常の検出が容易になる（標準からの逸脱が見える）
  ⑤ 属人化が解消される
```

---

## 2. 標準書の種類

| 種類 | 内容 | 使用者 |
|------|------|--------|
| 業務手順書（SOP） | 業務の手順・判断基準 | 担当者全般 |
| 作業標準書 | 製造作業の手順・条件 | 現場作業者 |
| 検査基準書 | 検査項目・合否基準 | 検査担当者 |
| 管理規定 | ルール・責任分担 | 管理者・担当者 |
| 用語集 | 用語の定義・統一 | 全員 |

---

## 3. 良い標準書の条件

```
① 目的が明確（なぜこの手順か）
② 手順が具体的（「適切に行う」ではなく「○○を○○する」）
③ 判断基準が数値・状態で定義されている
④ 例外処理が記載されている（「○○の場合は△△する」）
⑤ 最新版が管理されている（版数・改訂日が明記）
⑥ 現場担当者が実際に使える言葉と図で書かれている
```

## 4. Kaizen と 5S

### 4.1 5S の構造

```
整理（Seiri）：必要なものと不要なものを分け、不要なものを除く
整頓（Seiton）：必要なものを必要な時にすぐ使える場所に置く
清掃（Seiso）：きれいにし、異常をすぐに発見できる状態にする
清潔（Seiketsu）：整理・整頓・清掃の状態を維持する仕組みを作る
躾（Shitsuke）：決めたことを守る習慣を定着させる
```

### 4.2 Kaizen の本質

```
改善（Kaizen）の核心：
  大きな変革より、小さな改善を継続することが重要
  誰もが改善を提案・実施できる文化を作る
  改善は「専門家がやるもの」ではなく「現場全員がやるもの」

DXへの接続：
  デジタル化した業務も継続的な改善が必要
  現場の気づきを改善フィードバックとして取り込む仕組みを作る
```

## 5. 教育計画の設計

```
教育設計の手順：

① 必要スキルの定義
   → 役割ごとに「何ができればよいか」を定義する

② スキルマップの作成
   → 現状のスキルレベルと必要レベルのギャップを可視化

③ 教育プログラムの設計
   → 座学・OJT・e-Learning の組み合わせ
   → 習熟確認テスト・実技確認の設計

④ 習熟確認
   → 単に受講した（Input）ではなく、できる（Output）を確認

⑤ 変更時教育
   → 業務・システムが変わったら、変更点の教育を必ず実施
```

---

## 6. 横展開の設計

```
ある部門・案件で成功した改善を他に展開する：

横展開の条件：
  ① 成功の原因が明確に分析されている
  ② 他部門・他案件でも同じ問題があることが確認されている
  ③ 展開先での適用条件が違いを考慮して調整されている
  ④ 展開後の効果確認方法が設計されている

横展開しない判断：
  ① 成功が「その人だから」だった場合
  ② 環境条件が特殊すぎる場合
  ③ 展開コストが効果を上回る場合
```
