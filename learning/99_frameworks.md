## 1. 生産システムフレームワーク

### 1.1 トヨタ生産方式（TPS）

```
TPS の2本柱：

① ジャスト・イン・タイム（JIT）
   必要なものを、必要なときに、必要なだけ生産する
   → 過剰生産というムダを排除

② 自働化（Jidoka）
   異常が発生したら自動停止し、人に知らせる
   → 不良品を次工程に流さない
```

**7つのムダ（大野耐一）**
1. 作り過ぎのムダ
2. 手待ちのムダ
3. 運搬のムダ
4. 加工のムダ
5. 在庫のムダ
6. 動作のムダ
7. 不良・手直しのムダ

> 参照：[Toyota Production System（Ohno著）](https://www.amazon.com/Toyota-Production-System-Beyond-Large-Scale/dp/0915299143)

---

### 1.2 リーン生産方式

TPS を西洋向けに体系化したもの。5原則：
1. **価値（Value）**：顧客が価値と認めるものを定義する
2. **価値の流れ（Value Stream）**：価値の流れを特定しムダを排除
3. **流れ（Flow）**：価値を途切れなく流す
4. **引っ張り（Pull）**：顧客需要に引っ張られて生産
5. **完全（Perfection）**：継続的改善

> **ETO製造への適用注意**：JIT・カンバン等は量産前提のため直接適用不可。「プロセスのリーン化」（業務フローのムダ排除）として適用する。

---

### 1.3 TPM（Total Productive Maintenance）

**中島清一（Nakajima）が体系化（1988）**

```
TPMの8本柱：
1. 個別改善（設備の効率化）
2. 自主保全（オペレーターによる保全）
3. 計画保全（保全部門による計画的保全）
4. 教育訓練
5. 初期管理（新設備・製品の管理）
6. 品質保全
7. 事務効率化
8. 安全・衛生・環境
```

**OEE（Overall Equipment Effectiveness）：設備総合効率**
```
OEE = 可用率 × 性能率 × 品質率

可用率：計画稼働時間に対する実稼働時間の割合
性能率：実際の生産速度 vs 設計速度
品質率：良品率（不良品を除いた率）

世界クラス目安：OEE ≥ 85%
```

## 2. 品質管理フレームワーク

### 2.1 デミングの14原則（品質管理の思想的基盤）

主要原則（製造DXに関係する部分）：
- **原則1**：製品・サービスの改善を継続する目的を持て
- **原則3**：品質は検査に頼るな。最初から品質を作り込め
- **原則5**：問題を見つけるだけでなく根本原因を探れ
- **原則14**：全員を参加させて変革を実現せよ

### 2.2 ジュランの品質三部作

```
品質計画（Quality Planning）
  → 顧客を特定し、顧客ニーズを製品・プロセスに変換する

品質管理（Quality Control）
  → 計画に対する実績を評価し、差異に対応する

品質改善（Quality Improvement）
  → 突破口的改善プロジェクトを通じてパフォーマンスを向上する
```

### 2.3 DMAIC（Six Sigma の改善プロセス）

```
D：Define（定義）
   → 問題・目標・範囲を明確にする

M：Measure（測定）
   → 現状のプロセスパフォーマンスを測定する

A：Analyze（分析）
   → 根本原因を特定する（統計解析・RCA）

I：Improve（改善）
   → 根本原因を除去する解決策を実施する

C：Control（管理）
   → 改善された状態を維持する（標準化・管理図）
```

> 2023年研究：DMAICの「Analyze」フェーズにIoT・機械学習・プロセスマイニングを統合することで最大の効果が得られる

## 3. 情報システム標準

### 3.1 ISA-95 / IEC 62264 階層モデル

```
Level 4：ERP（企業経営レベル）
          → 売上・在庫・調達・財務

Level 3：MES（製造実行レベル）
          → 生産計画・指示・実績・品質記録

Level 2：SCADA・DCS（工程監視・制御）
          → センサーデータ・設備状態監視

Level 1：PLC（機械制御）
          → シーケンス制御・フィードバック制御

Level 0：物理的製造プロセス
          → 実際の加工・組立・計測
```

> **重要原則**：各レベルが持つべき情報責任を明確にする。MESがERP の責任を持ったり、ERP が設備制御に介入したりしない。

### 3.2 主要ITシステムの責任分担

| システム | 英語 | 主な責任 |
|---------|------|---------|
| ERP | Enterprise Resource Planning | 受注・調達・在庫・財務・原価 |
| MES | Manufacturing Execution System | 製造指示・実績収集・品質記録・トレーサビリティ |
| PLM | Product Lifecycle Management | 図面・BOM・設計変更・製品ライフサイクル |
| QMS | Quality Management System | 品質計画・不適合管理・是正処置・監査 |
| SCADA | Supervisory Control and Data Acquisition | 設備監視・データ収集 |
| CMMS | Computerized Maintenance Management System | 保全計画・履歴・部品管理 |

## 4. 変革・組織マネジメント

### 4.1 Kotter の8ステップ変革モデル

```
1. 危機意識を高める
2. 変革推進チームを作る
3. ビジョンと戦略を作る
4. ビジョンを伝える
5. 社員が行動できるよう障害を取り除く
6. 短期的成果を生む
7. 成果を積み重ねさらなる変革を進める
8. 変革を文化に定着させる
```

> DX推進においてステップ1〜3が最も難しく、最初に失敗する。

### 4.2 ADKAR モデル（個人の変革プロセス）

```
A：Awareness（認識）
   → なぜ変わる必要があるかを理解する

D：Desire（意欲）
   → 変革に参加・支持する意志を持つ

K：Knowledge（知識）
   → 変革のやり方・スキルを知る

A：Ability（能力）
   → 実際に変革を実行できる

R：Reinforcement（強化）
   → 変革を持続させ後戻りしない
```

## 5. 業務設計フレームワーク

### 5.1 SIPOC（プロセスの高レベル可視化）

```
S：Suppliers（インプットの供給者）
I：Inputs（インプット）
P：Process（プロセスのステップ）
O：Outputs（アウトプット）
C：Customers（アウトプットの受取者）
```

### 5.2 BPMN（業務プロセスの図示標準記法）

```
主要記号：
○ ：イベント（開始・終了・中間）
□ ：アクティビティ（作業・タスク）
◇ ：ゲートウェイ（判断・分岐）
→ ：シーケンスフロー（順序）
--- ：メッセージフロー（組織間の情報）
```

### 5.3 属人化防止の設計原則

```
判断の標準化：
  「誰が判断しても同じ結論になる」条件を文書化する
  
情報の一元管理：
  同じ情報を複数の場所で管理しない（二重入力の排除）
  
手順の可視化：
  暗黙知を形式知に変換する（手順書・フロー図）
  
引継ぎ設計：
  担当者が変わっても業務が止まらない設計
```

## 6. 設備保全フレームワーク

### 6.1 保全の種類

```
事後保全（BM：Breakdown Maintenance）
  → 壊れてから直す。コスト低いが停止コストが高い

予防保全（PM：Preventive Maintenance）
  → 定期的に点検・交換する。時間基準保全（TBM）

予知保全（PdM：Predictive Maintenance）
  → センサーデータで劣化を検知し最適タイミングで保全
  → Industry 4.0 の核心的応用

改良保全（CM：Corrective Maintenance）
  → 設備を改良して再発防止
```

### 6.2 予知保全の技術スタック

```
センサー（温度・振動・電流・圧力）
  → IoT Gateway（データ収集）
    → Edge Computing（リアルタイム処理）
      → クラウド（機械学習・異常検知）
        → 保全指示システム（CMMS連携）
```

## 7. データ・情報管理の原則

### 7.1 マスターデータ管理（MDM）

```
製造業における主要マスターデータ：
  品番マスター：品目の基本情報
  取引先マスター：顧客・仕入先・外注先
  設備マスター：設備台帳・属性
  工程マスター：工程定義・順序
  社員マスター：担当者・権限

原則：
  ① 一意のキー（重複しない識別子）
  ② 単一の正（1か所だけ保持）
  ③ 変更時の版数管理
  ④ 関連データの参照整合性
```

### 7.2 情報設計の主キー思想（製造業）

```
製造業における情報の結節点：

製番（製造番号）
  └── 案件ごとの全情報を束ねる

品番（部品番号）
  └── 部品・製品の識別子

工程番号
  └── 工程単位の実績・記録を束ねる

設備番号
  └── 設備の台帳・保全履歴を束ねる

検査番号
  └── 検査記録・合否判定を束ねる
```

## 8. KPI体系（製造業）

### 8.1 品質KPI

| KPI | 計算方法 | 目標の目安 |
|-----|---------|----------|
| 不良率 | 不良品数÷総生産数 | < 0.1% |
| 顧客クレーム件数 | 月次件数 | 前年同月比減 |
| 再作業率 | 再作業工数÷総工数 | < 2% |
| 工程能力指数（Cpk） | 計算値 | ≥ 1.33 |
| 初回合格率（FPY） | 手直しなし合格数÷総生産数 | > 95% |

### 8.2 納期KPI

| KPI | 計算方法 | 目標の目安 |
|-----|---------|----------|
| 納期遵守率 | 期日内納入件数÷総件数 | > 95% |
| LT達成率 | 目標LT内完了件数÷総件数 | > 90% |
| 設計変更処理時間 | 変更要求→承認→展開完了の時間 | 定義して改善 |

### 8.3 生産性KPI

| KPI | 計算方法 | 目標の目安 |
|-----|---------|----------|
| OEE | 可用率×性能率×品質率 | > 85%（世界クラス） |
| 計画外停止時間 | 月次合計 | 前年同月比減 |
| 段取り時間 | 実測平均 | SMED目標設定 |
| 工数効率 | 標準工数÷実工数 | > 90% |

### 8.4 Balanced Scorecard の4視点（製造への適用）

```
財務の視点：売上・利益・原価・投資回収
顧客の視点：品質・納期・顧客満足・クレーム件数
業務プロセスの視点：OEE・不良率・LT・再作業率
学習と成長の視点：スキルマップ達成率・標準書整備率・改善提案件数
```
